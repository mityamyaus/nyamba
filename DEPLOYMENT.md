# Нямба: APK и свой сервер

## APK

Готовый установщик: `artifacts/nyamba-0.1.0-debug.apk` (передаётся отдельно от исходников). Android 8.0+ и обновлённый Android System WebView. Это подписанная отладочная сборка для личного тестирования, не публикация в Google Play. При установке разрешите установку из выбранного источника.

По умолчанию открывается встроенное гостевое приложение: рецепты, настройки, планирование, конструктор и покупки работают локально. Серверный вход, поиск городов, карта и каталоги требуют собственного сервера. Кнопка **Сервер** в верхней панели позволяет ввести его HTTPS-адрес, например `https://food.example.ru`, или вернуться в локальный режим. Данные гостя встроенной версии и данные сайта хранятся раздельно, автоматически не переносятся. Экспорт списка открывает системный диалог сохранения текстового файла. Остальные ограничения прототипа по реальным ценам и составу товаров сохраняются.

Сборка из исходников: JDK 17, Android SDK 35/build-tools 35.0.0, переменные JAVA_HOME и ANDROID_HOME. На Windows `android\gradlew.bat -p android assembleDebug`, Linux/macOS `bash android/gradlew -p android assembleDebug`. Gradle 8.11.1 загружается wrapper-ом. APK: `android/app/build/outputs/apk/debug/app-debug.apk`. В GitHub Actions сборка запускается на push в main или вручную; скачивание во вкладке Actions → запуск → Artifacts.

Для будущих обновлений нужен тот же ключ подписи. Локальная debug-сборка и GitHub Actions используют разные отладочные ключи: они не обновляют друг друга поверх установленной версии. Для постоянного использования настройте собственный release-keystore и храните его резервную копию вне Git. Удаление приложения перед установкой сборки с другим ключом удаляет локальные данные. APK собран и подпись проверена; тест на реальном Android-устройстве ещё не проведён.

## Сервер

Нужен сервер с Docker Engine и Compose plugin, домен с DNS A/AAAA на этот сервер и открытые входящие порты 80/443. Удалите неверную AAAA-запись, если IPv6 не настроен. Исходники включают Dockerfile, compose.yaml и Caddyfile. Секреты и данные пользователей не входят в Git.

```sh
git clone https://github.com/mityamyaus/nyamba.git
cd nyamba
cp .env.example .env
```

В `.env` укажите `DOMAIN=food.example.ru` (без https:// и пути). Для настоящих SMS добавьте `SMS_RU_API_ID` и при необходимости `SMS_RU_SENDER`. Без ключа вход по SMS недоступен, гости могут пользоваться приложением. Не добавляйте `.env` в Git.

```sh
docker compose up -d --build
docker compose logs --tail=100
```

Откройте `https://food.example.ru`. Caddy получает TLS-сертификат и направляет запросы в Node-приложение, порт приложения наружу не публикуется. Данные аккаунтов и каталогов хранятся в Docker volumes `accounts` и `catalog`. Сделайте резервное копирование этих томов. **Не выполняйте `docker compose down -v`, если хотите сохранить данные.**

Обновление:

```sh
git pull --ff-only
docker compose up -d --build
```

Развёртывание на вашем сервере ещё не выполнялось. Это личный прототип: JSON-хранилище рассчитано на один процесс приложения, не на несколько реплик; публичные геосервисы и доступ к ценам магазинов имеют описанные в README ограничения. Публикация через GitHub Pages не заменяет Node-сервер.
